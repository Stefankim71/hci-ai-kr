01 · HCI / BASICS

What is HCI?

HCI는 Compute, Storage, Network를 하나의 Software-Defined Infrastructure로 통합하고, 분산·확장·자동화를 통해 인프라 운영을 단순화하는 차세대 데이터센터 아키텍처입니다.

THE CONCEPT

HCI는 무엇을 바꾸는가?

전통적인 인프라의 개별 시스템 중심 구조를 소프트웨어 중심의 통합 인프라로 전환합니다.

기존 3-Tier Infrastructure에서는 서버, 스토리지, 네트워크를 각각 설계하고 운영하는 경우가 일반적입니다.

HCI는 이 기능들을 소프트웨어 계층에서 통합하고 여러 노드에 분산하여 하나의 논리적인 인프라처럼 운영할 수 있도록 합니다.

CORE CONCEPTS

HCI를 이해하는 네 가지 핵심 개념

HCI의 구조를 이해할 때 자주 사용하는 네 가지 개념을 개념 소개와 VMware 관점의 세부 설명으로 나누어 봅니다.

Converged 개념소개Compute + Storage + Network를 하나의 플랫폼으로 통합 세부 설명 · VMware 관점VMware Cloud Foundation(VCF)은 vSphere 기반의 Compute 가상화에 vSAN Storage와 NSX Network를 결합해 하나의 Software-Defined 데이터센터 스택으로 운영하는 방향을 취합니다. 즉 서버·스토리지·네트워크를 물리적으로 하나의 장비로 만드는 것이 아니라, 각 자원을 소프트웨어 계층에서 추상화하고 공통 관리 체계로 연결하는 것이 핵심입니다.
Software-Defined 개념소개하드웨어와 기능을 소프트웨어 계층에서 추상화하고 자동화 세부 설명 · VMware 관점VMware는 vSphere, vSAN, NSX와 VCF Operations/Automation을 통해 Compute·Storage·Network·Management 기능을 소프트웨어로 정의하고 정책 기반으로 운영합니다. 하드웨어의 개별 설정에 의존하기보다 가상화와 정책, API 및 통합 관리 계층을 활용해 반복 작업을 표준화하는 것이 Software-Defined 접근의 핵심입니다.
Distributed 개념소개데이터와 서비스를 여러 노드에 분산하여 구성 세부 설명 · VMware 관점vSAN은 여러 ESXi 호스트의 로컬 디스크를 클러스터 차원의 공유 데이터스토어로 묶는 분산 스토리지 구조를 제공합니다. VM과 데이터 서비스는 클러스터 정책에 따라 여러 호스트의 자원을 활용하며, 네트워크와 관리 기능 역시 클러스터 전체를 대상으로 동작하도록 설계할 수 있습니다.
Scale-Out 개념소개노드를 추가하면서 성능과 용량을 함께 확장 세부 설명 · VMware 관점HCI에서는 단일 대형 서버를 교체하는 방식보다 클러스터에 노드를 추가해 자원을 확장하는 방식이 중요합니다. VMware HCI/VCF 환경에서도 클러스터 단위로 CPU·Memory와 분산 스토리지 자원을 확장하며, 실제 설계에서는 최소 구성, 장애 여유 용량, 네트워크 대역폭, 워크로드 증가량을 함께 검토해야 합니다.
ARCHITECTURE

HCI Architecture

HCI는 단순히 서버를 묶는 것이 아니라 Compute, Storage, Network, Management가 소프트웨어 계층에서 연결되는 구조입니다.

Compute

개념가상머신과 애플리케이션을 실행하는 CPU·Memory 계층 상세한 역할하이퍼바이저가 물리 CPU와 Memory를 가상화해 VM에 할당합니다. 클러스터에서는 HA, DRS와 같은 기능을 통해 워크로드 배치와 장애 대응을 지원하며, HCI에서는 Compute 자원이 Storage와 동일한 노드 자원 풀의 일부로 사용됩니다.

Storage

개념노드 내부 디스크를 활용해 분산 스토리지를 구성 상세한 역할HCI의 Storage 계층은 각 노드의 SSD/NVMe/HDD를 클러스터 단위의 논리적 데이터스토어로 구성합니다. VMware vSAN 관점에서는 정책 기반으로 데이터 보호와 성능 요구를 정의하고 여러 호스트의 디스크 자원을 활용합니다.

Network

개념노드 간 통신과 VM·스토리지 트래픽을 연결 상세한 역할HCI에서는 VM 트래픽뿐 아니라 관리, 스토리지, 클러스터 통신이 모두 네트워크 품질에 영향을 받습니다. VMware 환경에서는 vSphere Distributed Switch와 NSX를 활용해 가상 스위칭, 오버레이, 정책 및 보안 기능을 소프트웨어 계층에서 구성할 수 있습니다.

Management

개념가상화·스토리지·정책·모니터링을 통합 관리 상세한 역할관리 계층은 개별 장비 설정을 넘어 클러스터 전체의 구성, 수명주기, 모니터링과 정책을 다룹니다. VCF에서는 SDDC Manager와 VCF Operations/Automation 계층을 통해 배포·수명주기·운영 가시성을 통합하는 방향을 취합니다.

항목 영역은 최소화하고, 실제 인프라 운영자가 판단해야 하는 구조적 차이를 넓은 설명 영역에 배치했습니다.

항목
Traditional 3-Tier
HCI
구성
계층별 분리Server, SAN/NAS Storage, Network를 각각 설계하고 연결합니다. 각 계층의 호환성·용량·성능·이중화를 별도로 검토해야 합니다.
통합 플랫폼Compute, Storage, Network를 하나의 클러스터와 소프트웨어 관리 체계로 묶어 자원을 통합적으로 운영합니다.

운영
전문 영역 분리서버·스토리지·네트워크 담당 영역이 나뉘고 여러 관리 도구를 사용합니다. 장애 발생 시 계층 간 원인 분석과 협업이 필요합니다.
통합 관리클러스터 단위 관리와 정책 기반 운영을 통해 반복 작업과 구성 편차를 줄일 수 있습니다.
구축
통합 설계 필요서버·SAN·스위치·스토리지의 상호운용성과 케이블링, 펌웨어, 호환성 등을 종합적으로 검증합니다.
사전 통합 플랫폼검증된 노드와 소프트웨어 스택을 기준으로 설계해 구축 절차와 표준화를 단순화할 수 있습니다.
장애
계층별 영향 분석장애 지점에 따라 서버, SAN, 스위치, 스토리지 등 여러 영역을 확인해야 합니다.
분산·정책 기반 대응분산 구조와 클러스터 정책을 이용해 장애 도메인과 데이터 보호 수준을 설계하고 운영합니다.

CONSIDERATIONS

HCI 도입 시 고려사항

IT 담당자가 실제 도입 단계에서 고민하는 질문
“기존 인프라를 바꾸면 무엇이 좋아지는가?”에서 끝나지 않고, 성능·비용·이관·장애·운영 역량까지 함께 판단해야 합니다.

TCO · 비용

“초기 구축비와 5년 비용이 실제로 유리한가?”

라이선스, 유지보수, 서버·스토리지 증설, 전력·상면, 운영 인력까지 포함한 전체 TCO로 비교해야 합니다. 단순 장비 가격만으로 판단하면 안 됩니다.

Migration · 전환

“기존 VM과 데이터는 안전하게 옮길 수 있는가?”

기존 가상화 환경, 스토리지, 백업·DR 구조와의 연계성을 먼저 확인해야 합니다. 서비스 중단 시간과 단계적 전환 계획도 설계해야 합니다.

Availability · 장애

“노드 하나가 장애 나면 서비스는 계속되는가?”

노드 장애, 디스크 장애, 네트워크 장애를 각각 가정하고 N+1 여유, 데이터 보호 정책, 장애 도메인, 복구 시간과 성능 저하를 검토해야 합니다.

Security · 정책

“기존 보안정책과 충돌하지 않는가?”

네트워크 분리, 방화벽, 접근제어, 암호화, 관리망 분리와 같은 기존 보안 요구사항이 HCI 구조에서도 동일하게 구현되는지 확인해야 합니다.

Operation · 인력

“우리 운영팀이 새로운 플랫폼을 관리할 수 있는가?”

기존 서버·SAN 중심의 운영 역량에서 클러스터·가상화·분산 스토리지·정책 기반 운영으로 역량이 이동합니다. 교육과 운영 표준화까지 계획해야 합니다.
